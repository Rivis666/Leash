# Contributing to Leash

## If you're an engineer

Read [DESIGN.md](DESIGN.md) first. All 26 pages. Then:

1. Open an issue in the "design-question" template with your name, your
   area of expertise, and the section you want to work on.
2. Wait for a response. If the design needs revision in your area, we'll
   discuss it in the issue before any code is written.
3. Once the design is agreed, we'll set up the code repo (separate from
   this design repo) and start.

We are looking for:
- **Technical co-lead** (full-time, 18 months): Rust or C++, kernel-adjacent
- **Build infra** (full-time, 12 months): CI/CD, content-addressed storage
- **UX / daemon** (full-time, 12 months): DBus, GTK/Qt, systemd, Windows Service
- **ML / security** (full-time, 12 months): llama.cpp, prompt engineering, red team
- **Platform adapter** (part or full-time, 8 months): Win32, AppContainer, WDAC

## If you're not an engineer

- Read the doc. Open a "design-question" issue if something is unclear or
  you think a section is wrong.
- If you know a funder, a distro maintainer, or a conference organizer who
  should see this, introduce us.
- If you can write, help with the grant proposal (Section 12).

## If you're a funder or foundation

See Section 12 (Funding & Adoption Strategy) in DESIGN.md. The primary
target is the Sovereign Tech Fund. We need at least one credible technical
co-lead before submitting.

## Ground rules

- Be direct. "Section 5 is wrong because X" is the best possible comment.
- "This is interesting" is fine but not useful.
- If you think it already exists, link the project and explain the difference
  (or the lack thereof).
